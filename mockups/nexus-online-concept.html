The plan

A third client, not a second backend.

The web interface talks to the Nexus gateway that already runs on Debian, through Cloudflare Access. It adds no new server and no new write paths. Anything Desktop refuses, the web refuses too.

RO

Read-only by default

Every request goes through the same nexus-security catalog Desktop uses. Debian writes stay blocked; agents never get them.

ID

Access is the front door

Cloudflare Access with PKCE, the same flow the iPhone app uses. The site itself holds no passwords or SSH keys.

20s

Owner unlock needs the phone

The 4-digit, 20-second code from the iPhone app opens a 30-minute write window, matching Desktop.

↓

Also the public front page

Signed-out visitors see the landing page and Desktop downloads with SHA-256 sums. Everything else sits behind Access.

Before building

Four things to decide.

Domain

Which hostname should the site live on, and should the landing page be public or behind Access too?

Gateway routes

Does the gateway already expose telemetry over HTTP, or does phase 2 need new read-only routes on it?

Owner unlock on the web

Allow it from a browser at all, or keep Debian writes to Desktop and the phone only?

Framework

Astro is the suggestion. Say if you'd rather use SvelteKit, Next.js or plain HTML.
